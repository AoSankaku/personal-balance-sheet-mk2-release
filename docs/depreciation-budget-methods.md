# 予算分割振替と予算負担

購入額を複数月の費用に分ける仕訳と、予算上の購入負担・補填を管理します。家計管理のための費用配分として扱います。

| 方式 | 購入時の予算対象額 P | 毎月の予算対象費用額 m |
| --- | --- | --- |
| 割当済み予算・推奨 | 指定した購入負担予算を P 減額 | 通常予算 −m、購入負担予算 +m |
| 特別予算 | 購入専用予算を作り、0 から −P | 通常予算 −m、特別予算 +m |
| 未割当 | 個別予算には記録せず、元帳による資金減少を U に反映 | 予算振替なし。月々の費用計上は継続 |

P は取得額そのものではなく、購入仕訳の財源が予算対象資金を減らす額を上限にします。非追跡資金・予算控除対象外負債の部分には新たな予算負担を作りません。

T は元帳に基づく予算対象資産から予算控除対象負債を引いた額です。U = T − ΣB、D = Σmax(−B, 0)、配賦可能額 = U − D で、特別予算の負残高も含みます。月次補填は同額の予算内振替であり、T と会計損益を動かしません。

## 新規購入

入力のシンプル支出で予算分割振替を有効にし、資産・支払・費用の科目と振替期間を指定します。

1. 「割当済み予算」では「購入時の負担予算」と、費用科目の「予算割合」を設定します。月次振替元は、費用科目に設定された予算割合を初期値とし、複数の予算へ分割できます。購入負担予算と同じ振替元は選べません。購入負担予算の不足見込みは警告します。
2. 「特別予算」も同じ月次予算配分を使います。専用の特別予算は購入に関連付けて作成します。
3. 「未割当」では説明を読み、明示確認をチェックします。

保存リクエストの識別子は成功まで保持し、再送による購入・特別予算の重複作成を防ぎます。

### 月次振替元の割合と端数

作成・修正・日付指定の振替先変更では、各予算の割合と金額を手動調整できます。金額は表示した基準月の負担額です。金額から求める割合は整数％へ丸めずに保存し、他の月はその割合で配分します。初月の日割りや通貨の端数によって月ごとの金額は変わります。「勘定科目の予算割合を復元」で現在の科目設定を読み直せますが、保存済みの割合は科目設定を後から変更しても変わりません。

端数は各通貨の最小単位（円なら1円、USDなら1セント）で最大剰余法により分けます。小数部分が大きい予算から1単位ずつ配り、同率の場合は予算IDの昇順、未割当は最後とします。例えば5円を50%ずつ分けると3円と2円になり、振替元の合計と振替先への補填額は必ず一致します。

割合の合計が100%未満なら残りを未割当からの負担として表示し、確認後に保存します。100%超過は保存できません。未割当分は振替先を増額すると同時にUを減らしますが、Tや会計の損益を変更しません。既存の単一振替元は100%の設定として読み込み、明示的に修正するまでは従来の履歴を維持します。

非常に長い振替期間と多数の振替元を組み合わせ、完全な変更前後の監査記録を安全に保存できるサイズを超える場合は、保存前にエラーを表示します。期間または振替元の数を減らしてください。監査記録を省略したり、計画の一部だけを保存したりはしません。

## 既存データの設定・修正

既存計画をコード更新だけで新方式に移行しません。未設定の状態は、意図的に選んだ「未割当」と区別します。

1. 「財務諸表 → 予算」または「貸借対照表」の予算分割振替の欄から「予算分割振替の設定・修正」を開きます。未設定など対応が必要な計画は右上のやることリストからも直接開けます。購入仕訳の編集画面のボタンも利用できます。印刷用の財務レポートには編集操作を置きません。
2. 方式と必要な予算を選択します。必要に応じて適用日付きの振替元・先変更、一部／一括補填、予算補填の終了日を設定します。
3. 「変更をプレビュー」を押します。関連リセットの継続／終了、引継ぎ／一括補填、必要な同日順序を選びます。旧記録のリセット範囲が不明な場合、現在の科目数から全体リセットと決めつけず、範囲を確認します。
4. 購入・各リセット・現在の T/U/関係予算/配賦可能額、補填済み額・残額と、追加・変更・取消イベントを確認します。
5. 再プレビュー後、「プレビューした変更を適用」を押し、確認画面で適用します。

会計の購入・月次費用仕訳はこの修正では変更しません。計画に確実に紐づいた予算記録だけを置換します。出所不明の旧配賦は自動削除せず、プレビューで適用を止めます。プレビュー後の入力変更は競合として拒否し、再プレビューを求めます。

補填実績は計画の有効な振替・明示補填から算出します。通常の貯蓄配賦・予算リセット・将来予定は補填実績になりません。未補填額が残る場合は、修正画面で一括補填するか、負担を残して予算側の補填を終了します。

## 予算リセット

特別予算の負残高は既定で引き継ぎます。0 にする場合は、指定予算または未割当からの明示的な一括補填を記録します。補填終了後も会計の月次費用計上は続きます。

割当済み予算では、関係する予算のリセット時に継続／終了を選びます。過去の補填実績は保持します。終了しても未補填額を資金へ戻す操作や追加の支出を作りません。

「未割当」方式ではリセットに伴う補填は生成しません。将来の振替元・先を引き継ぐ場合は、修正画面で適用日付きの変更を保存してから科目をアーカイブします。履歴のある予算の削除や管理対象イベントの片側編集は保護します。

## データベースと検証

新しい append-only マイグレーションは `worker/drizzle/0016_depreciation_budget_methods.sql` です。計画設定・予算イベントの所有関係・修正履歴・リセット範囲・競合検知用 revision を追加します。旧計画を新方式へバックフィルしません。

導入時にはこのマイグレーションを適用します。すでに適用済みなら、画面配置・プレビュー高速化・月次振替元の複数配分の更新に追加マイグレーションは不要です。本番への適用時は AGENTS.md / README.md の完全 SQL バックアップ・復元検証手順が必要です。既存計画の予算設定の修復は、ユーザーが画面で確認して適用します。

API 回帰テストは `worker/tests/depreciationBudget*.test.ts`、画面検証は `worker/tests/depreciationBudget.browser.mjs` と `worker/tests/helpers/depreciationBudgetQaServer.ts` を使用します。後者はメモリ DB 専用で、既存 D1 を開きません。画面テストには別途インストール済みの Playwright のパスを渡し、フロントエンド開発サーバーと隔離 API を起動して実行します。

月次配分の追加検証は `worker/tests/depreciationBudgetSources.browser.mjs` と [月次配分の検証記録](testing/depreciation-budget-sources.tdd.md) を参照してください。

初期実装の検証対応表・カバレッジ・返金や科目統合の範囲は [検証記録](testing/depreciation-budget.tdd.md) を参照してください。
