# 予算分割振替の月次予算配分

## 意図と受入条件

- 新規作成・修正・日付別経路変更で、費用勘定科目の予算割合を初期値として使える。
- 割合と基準月の金額の双方を手動調整でき、勘定科目の既定値へ戻せる。
- 保存した配分はスナップショットとし、その後の勘定科目設定の変更で履歴を変えない。
- 通貨の最小単位で最大剰余法により分割する。同率は予算ID昇順、未割当は最後とする。各月の振替総額と予算対象費用額は一致する。
- 金額編集から作る割合を整数％へ丸めない。基準月以外は保存した割合で再配分する。
- 予算割合が100%未満の部分は未割当からの負担として表示し、明示確認を必要とする。100%超過を認めない。
- 既存の単一振替元設定とイベントキーを読み取れる。配分が複数の場合は振替元ごとの対になるイベントを保存する。
- 全ての振替元に対してリセット・アーカイブ・削除の保護が働く。
- プレビューと適用後の結果が一致し、既存の再試行・陳腐化検出・監査記録を維持する。

## 実装範囲

`budget_settings` JSONに配分を追加する。既存のSQLマイグレーションは変更しない。本作業では本番へのpush・デプロイや本番データの変更を行わない。

### 保存と上限

設定JSONには割合のスナップショットを保存する。旧単一振替元は100%として互換読取し、新形式は振替元ごとの対の記録を作る。未割当の振替は確認済み設定に限って受領実績へ含める。0%予算の削除や実在する月次仕訳の日付変更でも、修正・進捗が壊れないことを回帰検証した。

月次記録は分割したJSONで挿入する。監査行は完全な変更前後の内容を保ち、行全体の推定UTF-8サイズが1.8MBを超える計画は書き込み前に拒否する。600か月・10予算の新規作成と、530か月・4予算の継続リセットで、明示的なエラーかつ変更なしを検証した。

## 名称変更の追加要求

ユーザーの追加指定により、本機能の表示名を「予算分割振替」に変更する。費用を月々に割り振る意味に合わせ、費用科目とその予算割合を一連の設定として表示する。内部のAPI名・保存形式は互換性を維持する。

名称変更前のRED:

- `frontend/src/i18n/depreciationBudgetFeatureCopy.test.ts`: 6言語の機能名とラベルの12件が失敗。
- `worker/tests/budgetInstallmentTransferNaming.test.ts`: 新規の月次記録が `Laptop 減価償却費 (1/2ヶ月)` となり、要求した `予算分割振替` の名前を含まないため失敗。

## 手動金額と端数の画面RED

隔離APIで `worker/tests/depreciationBudgetSources.browser.mjs` を実行。5円を50%ずつに分けた3円・2円の表示から、生活費を2円、仕事費を3円と手動確定したとき、仕事費の割合が50%のままになり、期待した60%と一致せず失敗した。未割当10%が残る原因は、表示額と同じ数値を入力した場合に金額変更イベントが省略されること。割合の総和だけでは検出できないため、画面操作と保存割合の双方を検証する。
