# 預算系統（虛擬桶）

預算類別是建立在實際現金與銀行帳戶之上的虛擬桶。實際帳戶餘額保持不動，而預算系統則按用途劃分資金，例如自由花費、必要花費、旅行基金或投資準備金。

## 核心概念

| 項目 | 角色 |
| --- | --- |
| 帳戶 | 實際帳簿項目，例如銀行帳戶、信用卡、薪資或餐飲支出 |
| 預算類別 | 針對現金／存款的虛擬用途桶 |
| 連結的支出帳戶 | 決定哪些預算會被支出分錄消耗 |
| 目標持有帳戶 | 描述您打算將預算資金存放在何處 |

從設定 -> 預算設定建立類別。一個類別可以包含群組、目標餘額、餘額上限、溢位目的地、連結的支出帳戶及目標持有帳戶。

## 結轉、重置與上限

常規預算無論正負都會全額結轉。負預算代表超支，但現金流出已反映該超支，因此不會再次計入預算占用，也不會增加可分配資金。

若歷史匯入或修正導致餘額不切實際，請使用輸入 -> 預算調整 -> 預算重置將該類別歸零。總覽頁面會顯示該月的標記日期重置徽章。餘額上限可將超出的預算發送至其他類別。

## 收入分配與調整

收入分錄可套用預算篩選器將存款分配至各類別。篩選器使用固定、上限及比例分割步驟。手動預算調整之後可以增加或減少個別類別，並可包含選擇性備註。

## 預算配置

現金／銀行帳戶具有「納入可分配預算來源」設定。只有啟用的帳戶才會計入可分配現金，並作為預算配置中的實際餘額。

預算配置表出現在設定 -> 預算設定及財務報表 -> 預算 -> 預算一致性檢查中。

| 顯示 | 含義 |
| --- | --- |
| 目標 | 預期用於該帳戶群組的預算餘額 |
| 實際 | 目標帳戶的實際現金／銀行餘額 |
| 差額 | 實際減目標 |

目標金額採用與可分配資金相同的規則：只合計各類別的正預算餘額。負預算餘額不會抵減目標，而會以「未補足的預算超支」另行顯示。在預算頁面中可以切換「截至今天」與「包含未來收入」兩種口徑；資金缺口通知會開啟截至今天的檢視。

若一個預算連結到多個帳戶，或多個預算連結到一個帳戶，相關預算與帳戶會合併為一個群組。當存在差額時，提示會顯示應在各帳戶群組之間移動多少資金，或應增加或減少多少預算。

## 轉帳與預算移動

在簡易輸入中輸入帳戶轉帳時，您可以選擇同時移動預算。選擇來源與目的地預算類別以記錄預算轉帳，或將目的地留空以消耗／消失該預算，例如在動用準備金進行投資時。

實際轉帳與預算移動是獨立的事件。預算與帳戶的連結是配置指引；它們不會強制收入分配與銀行轉帳同時發生。

## 預算一致性 {#budget-reconciliation}

預算 -> 預算一致性檢查可檢測分錄金額與已儲存的預算分配金額之間的不一致。對於多行分錄及預算追蹤範圍外的交易，除非儲存了明確的分配，否則應用程式不會猜測預算類別。

將滑鼠停在詳細計算中的「？」圖示上，或以鍵盤將焦點移至該圖示，即可查看簡短說明。點擊圖示，或在觸控螢幕上輕點，可開啟本指南的對應章節。

比較時請使用相同的幣別與時間範圍。「截至今天」與「包含未來收入」使用的資料不同。下方日記帳問題清單的日期篩選不會改變上方的整體計算。

### 預算原資現金（C） {#budget-resources}

納入預算來源的現金與銀行餘額，減去需從預算扣除的負債。信用卡未付款預設會扣除。不包括排除於預算外的現金帳戶、購入資產及投資。雖然標籤提到現金，此數值已扣除所選負債。

### 全部預算餘額（包含負數）（N） {#budget-net-balance}

所有類別餘額的總和，包括負餘額。若 P 為正預算需求額，O 為未補足的預算超支，則 `N = P − O`。

### 純整合差額（G） {#budget-net-gap}

`G = C − N`。正數表示原資多於淨預算餘額；負數表示預算餘額多於原資。未分配資金、預留額及非現金費用調整也可能造成差額，因此非零不一定代表輸入錯誤。

### 非追蹤支出預留額（R） {#budget-reference-reserve}

用來另行預留非追蹤支出的欄位，目前為零；參考記錄不會占用一般預算。轉入排除帳戶的金額及參考記錄金額不會自動填入此欄位。

### 剩餘購入預留額 {#budget-purchase-reserve}

購入時建立的預留額中，尚未用於每月費用認列的部分。購入時已影響預算餘額，因此不會再次從純整合差額扣除。重設會清除先前的預留額。

### 重設後每月非現金費用抵減（D） {#budget-non-cash-offset}

重設清除購入預留額後，每月費用認列可能在沒有新現金支出的情況下減少預算。此抵減可避免這項減少變成新可分配資金。按類別加總「現金支出基準正餘額 − 一般正餘額」的正值部分；它可能與每月費用總額不同。

### 扣除預留額後的整合差額（A） {#budget-adjusted-gap}

`A = G − R − D`。從純整合差額扣除非追蹤支出預留額及非現金費用抵減。不要再次扣除剩餘購入預留額。若 R 與 D 均為零，A 等於 G。仍為負數可能代表原資減少但沒有記錄相應的預算減少；正數可能包含未分配資金。

### 正預算需求額（P） {#budget-positive-claims}

只加總正的類別餘額，不以負類別抵銷。這是讓所有正預算都能使用所需的原資。

### 已保留金額（S） {#budget-secured}

`S = P + R + D`。正預算需求額加上預留額及非現金費用抵減。

### 新增可分配金額／預算原資不足（F） {#budget-funding-gap}

`F = C − S = A − O`。結果大於或等於零表示還有新增可分配金額；負數表示預算原資不足。即使整合差額為零，只要還有負預算餘額，就會產生同等金額的原資不足。超支造成的現金減少已反映在 C 中，不要再從 F 扣除 O。

### 未補足的預算超支（O） {#budget-overspending}

負類別餘額絕對值的總和。可從其他預算補足，或分配後續收入。在類別間移動相同金額不會改變 N，因此也不會改變 G。

### 與預算配置過剩／不足的差異 {#budget-placement-gap}

預算配置過剩／不足是保管帳戶中的現金，減去該處所需的正預算、預留額及抵減。此階段尚未扣除信用卡未付款等負債。「轉帳後」欄位會推估為平衡預算配置而提出的轉帳方案執行後的結果；「扣除信用卡未付款後」總額也會扣除相關負債。轉帳可以改變個別帳戶的差額，但只在納入預算的帳戶間移轉資金，無法解決整體整合差額。

虛構範例：現金 `100,000`、可扣除的信用卡未付款 `10,000`、類別餘額 `100,000` 與 `−15,000`、R 為 `2,000`、D 為 `3,000`。目前 R 為零。

| 項目 | 計算 |
| --- | --- |
| 原資 C | 100,000 − 10,000 = 90,000 |
| 淨預算 N | 100,000 − 15,000 = 85,000 |
| 純整合差額 G | 90,000 − 85,000 = 5,000 |
| 扣除後差額 A | 5,000 − 2,000 − 3,000 = 0 |
| 已保留金額 S | 100,000 + 2,000 + 3,000 = 105,000 |
| 原資不足 F | 90,000 − 105,000 = −15,000 |
| 配置差額總計 | 100,000 − 105,000 = −5,000 |

此例中整合差額為零，但未補足的預算超支是 `15,000`，原資不足為 `−15,000`。配置差額 `−5,000` 還未扣除信用卡未付款，因此不同於原資不足。

### 檢查轉入排除帳戶的轉帳 {#budget-excluded-transfers}

若收到未追蹤現金，同時從已納入的銀行帳戶匯出相同金額，家庭資產只是交換形式，但預算原資 C 會減少。若未記錄相同金額的預算減少，N 不變，G 與 A 會降低。在簡易輸入中，將付款預算選為「預算轉出方」，並將「預算轉入方」選為「消滅」，即可減少預算。只在類別間移轉不會減少 N。

即使沒有費用科目，檢查也會提示轉入排除帳戶的轉帳缺少預算減少。複合分錄同時包含費用及轉入排除帳戶時，檢查會考量已儲存的預算減少。若刻意使用未分配資金，原資減少會動用這筆餘額；檢查提示不會自動減少任何預算。
